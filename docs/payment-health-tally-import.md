# Production configuration notes — do not include as customer questions

- Keep the form private/unlisted until testing is complete.
- Require the email field and required acknowledgements.
- Restrict uploads to sensible business-document formats where Tally permits (PDF, DOC/DOCX, XLS/XLSX, CSV and common image formats only where genuinely useful).
- Set a conservative per-file size limit; the service expects representative documents, not bulk archives.
- Do not add Google Sheets, Zapier, CRM, AI or other integrations during validation.
- Enable 2FA on the account before accepting real customer evidence.
- Test with fictional files before publication: submit → inspect → download → verify → delete → empty Trash → record result.
- Do not publish a specific deletion promise until that live test confirms the operational process.
- Use status sequence: PAID → INTAKE OUTSTANDING → INTAKE RECEIVED → READY FOR REVIEW → REVIEWING → QA → DELIVERED → FOLLOW-UP.
